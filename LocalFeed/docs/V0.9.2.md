# LocalFeed v0.9.2

## Scope

Only inbox recovery and card-game presentation change. The video player pool,
feed bindings, thumbnail loader, album ordering and image reader gestures are unchanged.

## Inbox recovery

- Record the actual target tree. Legacy journals recover their tree from the saved copy URI.
- Match document authority and document ID, not the spelling of a tree-granted URI.
- Find an existing journal for the same source document across rule changes and legacy keys.
- Explicitly query directory IDs and compare the DocumentFile listing. Null, failed or partial
  queries cannot be treated as proof that a copy has disappeared.
- A missing unfinished temporary copy can be recreated after successful queries.
- When the target changes, keep the old app-owned temporary copy until the new target copy
  passes length and SHA-256 checks. Persist both locations so interruptions can resume.
- Delete only the exact recorded `.localfeed-*.part` replacement residue; ordinary files in
  the old directory are retained. An existing final archive in the old target blocks migration
  with instructions to select the old target again; it is not duplicated or deleted.
- Authorization, write, rename, cleanup and source-delete failures remain visible in task details.

## Cards

- Measure fitted frames before child measurement, including LinearLayout weight passes.
- Switching between horizontal and vertical layouts changes existing slots only. No image
  clear, view recreation, game advance or thumbnail reload occurs during the switch.
- Long-press uses a full-window photo dialog with a floating accessible close control.
  There is no fixed 560dp container and no reserved button footer. Letterboxing still exists
  where required to show the complete photo without cropping.

## Verification boundaries

`tools/DownloadInboxTest.kt` covers baseline transfer, wait, rename and write failures,
restart after source-delete failure, legacy target migration, URI aliases, missing temp,
provider query failure, retention of an old final archive, interrupted migration cleanup,
and changed source content. The provider is a stub; real Android providers and phone UI
must still be validated on-device. CI also compiles the actual Android app with the fixed key.

On-device acceptance: repeat layout switches before/after images load, test both orientations
and memory front cards, pinch/double-tap the full-window preview, retry an existing legacy
inbox failure, and confirm the final task details and files in both source and target.
