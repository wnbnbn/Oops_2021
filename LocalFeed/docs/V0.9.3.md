# LocalFeed v0.9.3 开发与验收交接

版本 0.9.3，versionCode 21，包名 com.localfeed.app。固定签名证书 SHA-256：
`2fcf7ed9c4823aa9589c53102b559de274b7ab84f636ded79957aa88746ab7a6`。

## 本轮反馈与实现对应

| 反馈 | 代码处理 | 边界 |
| --- | --- | --- |
| 收件箱慢，扫描像被堵塞 | 快速索引先执行，独立 inbox 工作线程每文件让出公平锁；元数据每 25 项让出锁 | 一个大文件的复制和校验仍占锁；底层 SAF 耗时没有被消除 |
| 归档的图片长时间看不见 | 每个校验成功副本安排叶节点入库，750 ms 合并调度、每批最多 16 项 | 调度时间不是显示时限；提供器延迟与锁竞争可能继续等待 |
| 卡牌放大后无法处理文件 | 全屏预览左上更多菜单：信息、分享、外部打开、最近删除、永久删除 | 删除需确认且退出未完成对局，交回主界面现有队列 |
| 点图片外留白也选胜者 | 点击与长按绑定拟合卡片 frame，不绑定外层权重 slot | 边框计为卡片，外围槽位空白不计 |

## 文件与责任

- core/InboxWork.kt：进程共享公平文件锁、收件箱单实例门、按文档去重的有界发布队列。
- data/DownloadInbox.kt：规则、稳定性判断、转移日志、内容校验、文件完成事件，不依赖播放器。
- data/MediaRepository.kt：快速索引、25 项元数据批次、独立 inbox worker、合并入库调度。
- data/TreeScanner.kt：全目录两阶段扫描及 indexArchived 单叶节点入口；增量入口没有 pruneRootNotSeen。
- data/MediaIndexDb.kt：recordsForDocument 用提供器 authority + 文档 ID 匹配不同树授权下的同一源文件。
- MainActivity.kt：合并增量媒体源、隐藏相册延后刷新、卡牌删除结果接回现有持久任务中心。
- ui/CardHallActivity.kt：拟合卡片触控范围及预览菜单；没有另建 TaskCenter 或自行删除源文件。

## 执行过程

1. 主界面扫描进入 indexIo，扫描媒体目录的廉价字段，调用 onIndexed；此步不做收件箱复制。
2. 收件箱在独立 inboxIo 上开始。InboxWork.begin 保证整个进程同时至多一个收件箱扫描。
3. 元数据在 metadataIo 每次 25 项持有共享文件锁，批间释放；删除、转移、索引等待同一公平锁。
4. 每个候选转移只在该文件处理过程中占锁。已持久保存日志；内容校验成功才能删除来源。源记录在来源删除后、仍持锁时立即清除，避免延后查 URI 误删同路径的新下载记录。
5. onArchived 在锁外触发，包括“归档成功但来源删除失败”的部分成功。按归档 URI 合并待处理项，750 ms 后在 indexIo 每批最多索引 16 项，失败最多重试两次，再在任务中心给出索引失败及重扫建议。
6. indexArchived 规范化归档 URI 到目标目录授权，读取四个廉价字段，上调单条记录并补充必要元数据，不清扫其他媒体记录。
7. 主界面合并记录与被移走来源 ID。新到达记录只更新 session 的媒体源，不重建已有随机队列；实际被删除来源才使旧队列条目失效。
8. 隐藏相册不重复排序、差分和绑图；重新显示且窗口取得焦点时刷新。不会重新生成随机排序种子。

## 转移速度与安全性

首次新文件由“预读来源 + 复制来源 + 最终复读来源”减少到“复制时计算 SHA-256 + 最终复读来源”，测试校验来源读取次数为 2。归档临时文件与最终归档仍完整校验，原有恢复日志、迁移旧目录、保留源文件、不同授权 URI、同名不覆盖规则不降级。

已有日志中的非空 hash 必须继续验证，不允许因优化覆盖已知内容不同的副本。首次发现或大小/修改时间变化后，仍需至少 30 秒后下一次扫描确认稳定，不代表下载器提供了正式完成信号。

暂停或移除规则在下一文件边界生效，不截断进行中的写入。一个超大文件仍可能让其他文件操作等待；本轮没有增加并发复制，也没有使用前台服务。进程被系统终止时，本轮线程停止，下次扫描用日志恢复，绝不可承诺关闭应用后继续转移。

## 卡牌预览与删除

右上关闭、左上更多，图片双指与双击手势继续由既有 ZoomImageView 承担。更多菜单操作不触发选胜者。

信息保留完整目录、大小、尺寸、修改时间、点赞和收藏，不展示冗长 content URI。分享与外部打开传递 URI、MIME、ClipData 和临时读取权限，失败显示原因。

删除经过显式确认，用 Activity Result 将一个媒体 ID 和删除方式传给 MainActivity。主界面重新读取记录并排除已排队目标，再通过 batchTrash 或 batchPermanentDelete 执行。删除会返回相册并结束未完成对局，不自动判另一张胜，不保存未完成对局结果；此前已完成战绩保留。退出时关闭所有图片预览 Dialog 再释放缩略图，避免窗口泄漏。

## 自动检查与验证方法

在 LocalFeed 目录运行 `bash tools/run-smoke-tests.sh`；需 kotlinc 与 Java。之后 `gradle :app:assembleDebug --stacktrace --no-daemon`。完整依赖和构建流程见根 README。

新增测试：

- InboxWorkTest：收件箱单实例、异常释放、合并替换、16 项取批、多线程去重、共享锁互斥及公平文件边界。
- DownloadInboxTest：旧日志恢复、迁移中断、权限读取失败、非覆盖、源内容变化；新增双文件逐项发布、锁外回调、锁内源记录清理、来源只读两次、删除失败也发布归档、暂停不遗留中断副本。
- TreeScannerInboxTest：叶节点入库、归档授权 URI 规范化、元数据补充、保留其他记录与状态、不根目录清扫、临时文件拒绝、失败关闭 Cursor、跳过已移除元数据任务。
- 现有 CardGeometry、CardGames、FeedEngine、FeedSession、AlbumQuery、SimilarVideoScanner 测试保持运行。

桩提供器测试验证程序行为，不验证 Android 原生解码器、真实 DocumentsProvider 吞吐、实机触控。CI 还检查源码精确路径清单和 SHA-256、Android 编译、固定 APK 证书。发布由这些门控通过后执行；BUILD_REPORT 记录提交与 CI。

## 必须真机核验

- 来源放入 20 张图片，首次扫描等待稳定，30 秒后再扫描；转移未全部结束时，已完成图片应逐渐进入相册。
- 同时进入任务中心，快速索引不应等待全收件箱完成；大文件转移期间观察仍可能等待的时间，不当作恒定显示时限。
- 正常浏览已有视频时有新图片到达，播放队列和当前视频不得重排或闪帧。
- 归档目录包含其他图片，增量入库不得删除其相册记录、点赞与收藏。
- 来源拒绝删除时检查“已归档但来源删除失败”：归档可见、源保留、再扫不能生成第二个归档。
- 转移中退出应用并重开扫描，确认恢复无重复、无源文件未校验删除。
- 锦标赛和生存擂台分别检查上下/左右布局的空白区域不选胜者；实际图片可点击，长按不误投票。
- 预览查看信息、分享及其他应用；最近删除可恢复，永久删除确认后不可恢复，队列记录应显示结果。
- 删除取消后继续对局；确认删除后返回相册并保留此前已完成战绩；反复打开关闭预览无闪退。

本轮不修改视频 Surface/播放器池、卡牌升级阈值、游戏计分、图片阅读器或随机权重。不要为了收件箱性能改动已稳定播放链路。
