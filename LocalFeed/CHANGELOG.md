# 0.8.0 三播放器滑动窗口版

- 视频 Feed 从单 ExoPlayer 跨页面搬运改为 Media3 官方 `PlayerPool` 三播放器滑动窗口；当前页、上一页和下一页各自保持播放器与 Surface，不再每次翻页执行清 Surface、换绑和冷启动。
- 已附着的相邻页会提前取得 `DefaultPreloadManager` 媒体源、准备解码器并渲染自己的首帧；页面选中后只切换唯一活动播放器的音量与播放状态。
- 滑动过程不再主动暂停当前视频；松手后无需等待重新 `setMediaItem()` 和 `prepare()`，解决快速翻页先停一下再继续的问题。
- 删除 v0.7.3 的 90 ms 缩略图淡出。页面首帧按具体 PlayerView 精确归属，准备完成的相邻页直接隐藏自己的海报，避免同一媒体重复出现时串页。
- 预加载范围固定为当前位置前后 3 项，播放器池固定为 3；随机队列中的重复媒体按“媒体 ID + 队列位置”建立独立媒体源，避免两个页面共享一个预加载实例。
- 视频海报提取限制为单线程，并在 Android 10 以上优先使用系统 `loadThumbnail`；降低 `MediaMetadataRetriever` 与播放解码器、SAF 读取之间的资源竞争。
- 短视频离开活动页时归零，返回后从头播放；长视频保留原有播放位置逻辑。退出 Feed、删除页面和回收 ViewHolder 时会取消等待并归还播放器。

# 0.7.3 分页快照与快速切换修复版

- 媒体数据库的可见列表与最近删除列表改为每页 200 项读取；每页游标读取完成后立即关闭，避免 3000 项以上、长 SAF URI 与图片解码并发时耗尽 Android `CursorWindow`。
- 元数据扫描完成后的界面快照纳入同一存储锁，分页期间不会被删除任务改变数据集，避免偏移分页漏项或重复项。
- 快速连续切换视频时，当前视频缩略图不再在首帧到达后瞬间硬切消失；改为仅对匹配媒体执行 90 ms 淡出，继续隔离旧页面和旧播放器回调。
- GitHub 根 README 重建为完整项目入口，补齐架构、数据流、模块职责、构建签名、发布、性能边界、测试和人类/AI 接手顺序。

- 单图和瀑布流的双指缩放提高响应，瀑布流支持缩小复位及更灵敏的横向移动。
- 检查更新优先读取双线路轻量清单并设置短超时，再回退 GitHub Release API；减轻部分网络环境下长期 timeout。
- 进度条附近的单击不再触发暂停；铺满状态图标改为干净的单正方形外框。
