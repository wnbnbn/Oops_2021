# v0.8.1 应用内更新验证

- 构造 CDN 返回 v0.7.2、原始清单和 Release 返回 v0.8.1 的场景；检查结果必须选择 v0.8.1，不能因最先返回的旧清单提示“已经是最新版”。
- 分别让原始清单、Release API、CDN 单独超时或失败；只要任一路线在 11 秒内成功，检查更新就应给出该轮可获得的最高版本。
- 检查三个请求均带独立防缓存时间戳，普通清单请求带 `Cache-Control: no-cache, no-store` 和 `Pragma: no-cache`。
- 从 v0.8.1 开始验证后续发布：检查、下载、SHA-256 校验、系统覆盖安装及任务中心状态均正常。

# v0.8.0 播放核心重构验证

- 连续慢滑视频，拖动过程中下一页应已经显示自身真实首帧；松手后直接播放，不得闪现上一视频或当前视频缩略图。
- 连续快速切换 30 次以上，再反向连续切换；每次停留页都应自动播放，不能先卡住再继续，不能等待拖动进度条后才恢复。
- 对比短视频和长视频：短视频离开再返回必须从头开始，长视频仍按阈值保存和恢复位置。
- 快速往返包含同一媒体多次的随机队列，首帧、进度、点赞按钮和播放错误必须属于屏幕上的具体页面，不能按媒体 ID 串到另一个重复页面。
- 滑动期间只有当前页产生声音；页面稳定后旧页立即静音暂停，新页接管音频，不能出现双重声音。
- 进入横屏、退出横屏、切换铺满模式和前后台返回时，不应重新冷启动当前视频；显示比例与原功能保持一致。
- 播放过程中打开相册、图片阅读器、任务中心，再返回 Feed；播放器池应正确回收或恢复，无闪退、黑屏及后台声音。
- 在包含 H.264、HEVC、高分辨率和问题视频的混合媒体库测试三播放器池；解码失败只影响对应页面，应用不能崩溃。
- 将当前页、相邻页加入永久删除任务；文件删除前必须释放对应播放器和预加载源，剩余页面继续正常播放。
- 在 100 GB 级目录扫描或复制文件时快速切换，缩略图提取不得明显抢占播放，任务中心不得再次出现 `CursorWindow` 行读取错误。

- 断开 GitHub API 或制造慢网络，检查更新应由清单线路成功或在短超时后明确失败，不能无限 timeout。
